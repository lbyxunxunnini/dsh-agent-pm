# DSH 插件专项审查

只在审查对象是 DeepSeek Harness（DSH）插件时读取本文件。通用维度仍按 `checklist.md` 执行；这里补的是 DSH 特有的失败点。

## 先确认插件形态

| 形态 | 入口 | 主要风险 |
|------|------|----------|
| 技能包插件 | `ctx.skills.registerProvider()` 或 `ctx.skills.register()` | 技能发现、frontmatter、资源路径 |
| 工具插件 | `ctx.tools` 注册模型可调用工具 | schema、权限、取消、幂等 |
| 命令插件 | `ctx.commands` 注册人类命令 | 参数校验、错误输出 |
| 事件插件 | 监听 `agent/*`、`tools/*`、`session/event` | 监听器泄漏、阻塞主流程 |
| 模型适配插件 | `ctx.llm` 注册适配器 | 流式协议、错误重试、用量统计 |
| 界面插件 | Web Client / ConversationNode | 渲染性能、状态同步 |

## 清单与加载

- `package.json` 是否声明 `dsh.bundle.patch`，且路径真实存在。
- `cordis.patch.yml` 是否是“数组 + `insert`”结构，`id` 是否唯一，`name` 是否能被 Node 解析到。
- 包名、patch 行 id、插件导出的 `name` 是否一致；不一致时排查加载失败会很难。
- `files` 是否包含 `lib`、`skills`、`cordis.patch.yml`、README 和 LICENSE；npm 发包后缺文件是常见 P0。
- 是否声明 `engines.dsh` 或相应的 peer 依赖范围；DSH 是开发者预览，版本不匹配应显式拒绝，而不是运行时崩溃。

## 技能包插件

- `inject` 是否包含 `skills`；没有注入就调用 `ctx.skills` 会在启动时失败。
- `list()` 是否只读 frontmatter，不读正文；正文应在 `get()` 中按需加载。
- frontmatter 的 `name` 是否符合 kebab-case，`description` 是否在 500 字符内且能区分触发场景。
- 多行 `description: |` / `>-` 是否被正确解析；把 `|` 当普通字符串会导致技能目录里没有描述。
- `get()` 返回的 `resourceBase` 是否指向技能目录；脚本、references、示例的相对链接才能被解析。
- 技能目录是否随包分发；只打包 `lib` 会导致 `list()` 返回空目录。
- 同名技能的处理策略是否明确：宿主层、项目层、用户层谁覆盖谁。

## 工具插件

- 工具名是否稳定、语义是否单一；不要把多个动作塞进一个工具靠参数分支。
- schema 是否声明必填项、枚举、默认值；模型看不到的限制等于没有限制。
- 是否有取消路径；长任务必须响应 abort，不能吞掉取消信号。
- 失败是否返回可行动的错误，而不是抛裸异常或静默成功。
- 有副作用的工具是否幂等或可回滚；删除、写入、发布类操作是否要求确认。
- 工具结果是否控制体积；把整个文件或整个网页塞进上下文会造成上下文膨胀。

## 事件插件

- 监听器是否通过 `ctx.effect()` 或插件生命周期登记；卸载后是否自动清理。
- 是否在瀑布事件里正确调用 `next()`；漏调会截断后续监听器。
- 是否在事件回调里做长时间同步工作，阻塞 turn / step。
- 是否把“观察”写成“修改”；只读通知不应改变会话状态。
- 事件失败是否被隔离；一个插件抛错不应让整个会话不可用。

## 安全与权限

- 插件是否读取或写入工作区之外的路径；DSH 的沙箱和审批策略是否被绕过。
- 是否读取凭据、环境变量或用户配置；读取范围和用途是否在 README 说明。
- 是否发起网络请求；目标、数据、失败降级是否明确。
- 是否在安装或启动时执行外部命令；git 安装的 `prepare` 脚本尤其要提示用户。

## 报告时的定级建议

- **P0**：插件无法加载、技能目录为空、资源路径失效、越权读写、卸载后监听器仍生效。
- **P1**：技能 description 丢失导致无法触发、工具 schema 缺必填项、长任务不可取消、错误静默成功。
- **P2**：技能描述不够区分、工具结果过大、事件回调有轻微阻塞、README 安装步骤不完整。
- **P3**：命名不统一、注释缺失、示例过时。

## 验证动作

至少执行以下一项，不能只读代码：

1. 在隔离的 `DSH_HOME` 下执行 `dsh plugin --profile <test> add <本地目录>`。
2. 执行 `dsh --profile <test> --dump-config`，确认插件层出现且没有加载错误。
3. 启动测试 profile，确认技能目录出现 `agent-pm`，并能用 `skill` 工具加载正文。
4. 卸载插件，确认技能目录消失、监听器不再触发。
