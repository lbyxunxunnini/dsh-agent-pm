# 常见问题

## 使用类

### Q: 审查要多久？

轻量项目（单个 Skill 文件）1-2 分钟，复杂项目（多文件 + MCP Server）3-5 分钟。产品评审额外 2-3 分钟。

### Q: 能审查 DSH 项目吗？

支持。agent-pm 覆盖 Claude Code 和 DeepSeek Harness（DSH）生态，支持四类项目：
- Skill 文件（Claude Code `SKILL.md` / DSH `<name>/SKILL.md`）
- CLAUDE.md / AGENTS.md / 指令文件
- MCP Server
- DSH 插件（技能包 / 工具 / 事件插件）

LangChain、AutoGen 等非 Claude Code / DSH 框架不在审查范围内。

### Q: 审查结果不准确怎么办？

每个问题都有验证步骤（5 步验证法），你可以质疑任何问题。用 checklist.md 中的"反模式清单"自查：
- 两处措辞不同 ≠ 矛盾
- 概念与实现差异 ≠ bug
- 工具覆盖度缺口 ≠ 功能逻辑 bug

### Q: P0/P1/P2/P3 什么区别？

| 级别 | 含义 | 处理方式 |
|------|------|---------|
| P0 | 必须改，会导致危险操作/数据丢失 | 阻塞，必须修复 |
| P1 | 必须改，主流程断裂/关键前置缺失 | 阻塞，必须修复 |
| P2 | 建议改，表达不稳定/边界不完整 | 进入 backlog |
| P3 | 记录即可，风格/措辞优化 | 只记录 |

### Q: 三方评估法是什么？

产品评审的评分方法，确保客观公正：
1. **支持方** — 列出优点（至少 5 条）
2. **反方** — 列出缺点（至少 5 条）
3. **综合方** — 基于双方观点逐维度评分

反方观点有约束：禁止"没有实战验证""用户是否会遵守"等模型不可验证的批评。

### Q: 目标治理和过程控制什么关系？

- **过程控制**：确保 Agent 不走错路（禁止/必须/不得）
- **目标治理**：帮 Agent 理解什么是好结果（目标/验收/品质/评估）

两者要平衡。过程控制 > 80% 时系统趋于僵硬。

### Q: 审查报告能保存吗？

能。审查完成后说"存一下"，报告会写入项目根目录的 `AGENT-PM-REVIEW.md`。

### Q: 候选规则是什么？

agent-pm 的进化机制。当同一问题在 2 个及以上不同项目中出现时，会提炼为候选规则。经用户确认后，才正式加入审查清单。

## 理解类

### Q: agent-pm 和 code review 有什么区别？

| 维度 | agent-pm | code review |
|------|----------|-------------|
| 视角 | 产品经理 | 工程师 |
| 关注点 | 设计质量、指令清晰度 | 代码质量、性能 |
| 审查对象 | Skill/CLAUDE.md/MCP Server | 实现代码 |
| 输出 | 问题报告 + 修复建议 | 代码修改建议 |

### Q: 9 个维度怎么选？

根据项目类型自动选择：
- **Skill 文件**：指令层、工作流层、逻辑正确性、设计质量、目标治理层必检
- **CLAUDE.md**：同上，工具层选检
- **MCP Server**：工具层、工作流层、逻辑正确性、设计质量必检

不适用的维度直接跳过，不强行凑问题。

### Q: ReviewSpec 是什么？

每轮审查开始时固定的审查参数，包括：
- 项目类型
- 启用/排除的维度
- 最大问题数
- 严重程度阈值

作用：防止审查过程中临时扩大范围，确保修复验证只验证已确认问题。

### Q: 产品评审是必须的吗？

不是。技术审查完成后会询问是否继续产品评审，用户可以选择跳过。

产品评审主要回答"这个项目做得好不好"，技术审查回答"这个项目有没有 bug"。

### Q: 如何只做产品评分，不做技术审查？

直接说"产品评分""给这个项目打分"或使用 `/agent-pm /path/to/project --score`，即可直接进入模式 D。

模式 D 是独立的一等模式，会直接执行三方评估、维度评分、目标治理分析、发展方向和用户接受策略，不会先跑技术审查。详见 [mode-d.md](mode-d.md)。

如果项目有历史技术审查记录（issue-ledger 中保存的上下文），模式 D 会自动恢复并引用这些发现作为评分参考。

### Q: 修复模式会改坏我的代码吗？

不会。修复前有安全准备（备份确认），修复后有验证（diff 驱动），只验证已确认问题和 P0/P1 回归。如果修复失败，会明确告知哪些条件未通过。
