# 产品评审示例

> 以下是一份完整的产品评审示例，展示三方评估法和评分流程。

---

## 背景

基于 [example-fix-flow.md](example-fix-flow.md) 的修复结果，用户选择继续产品评审。

项目：task-driver（任务驱动型 Skill）

---

## 价值评定（三方评估法）

### 支持方观点（优点）

1. **任务拆解逻辑清晰** — 将复杂任务拆解为独立子任务，降低用户认知负担 — SKILL.md:45-60
2. **依赖关系处理完善** — 识别子任务依赖、生成依赖图、检测循环依赖，执行顺序有保障 — SKILL.md:62-75
3. **用户确认机制** — 拆解后让用户确认，避免执行错误方向 — SKILL.md:78-85
4. **角色边界明确** — "不做的事"章节清晰定义了 agent 的边界 — SKILL.md:22-28
5. **流程闭环** — 从接收任务到汇报结果，每个步骤都有明确的输入输出 — SKILL.md:90-100
6. **错误处理有设计** — 循环依赖检测、用户拒绝重试，异常路径有覆盖 — SKILL.md:70, 85
7. **输出格式定义** — 依赖图有 JSON 格式定义，可机读 — SKILL.md:65-73

### 反方观点（缺点）

1. **触发条件模糊** — "复杂任务"无量化标准，用户不确定何时触发 — SKILL.md:8 — 检查类型：可执行性
2. **无重试/降级机制** — 子任务执行失败只告知原因，无自动重试 — SKILL.md:95 — 检查类型：完整性
3. **缺少验收标准** — "子任务执行完成"不等于"任务目标达成" — SKILL.md:100 — 检查类型：完整性
4. **输出格式单一** — 只有 JSON 格式，非技术用户难以阅读 — SKILL.md:65 — 检查类型：可执行性
5. **无进度反馈** — 长时间执行时无中间状态反馈 — SKILL.md:90-100 — 检查类型：完整性
6. **token 效率未优化** — 依赖图 JSON 格式冗长，可简化 — SKILL.md:65-73 — 检查类型：资源消耗
7. **无示例** — 缺少完整的使用示例，用户需要自己摸索 — 全文 — 检查类型：可执行性

## 目标治理综合分析

### 过程控制 vs 目标治理

- **过程控制规则**: 8 条
  - "必须拆解为子任务"
  - "必须生成依赖图"
  - "必须检测循环依赖"
  - "必须按依赖顺序执行"
  - "必须让用户确认"
  - "必须汇报结果"
  - "不做代码实现"
  - "不做架构设计"

- **目标治理规则**: 3 条
  - "帮助用户拆解复杂任务"（目标定义）
  - "每个子任务独立可执行"（验收标准）
  - 无品质锚定、无评估维度

- **比例**: 8:3（过程控制 73%，目标治理 27%）

- **判断**: 偏向过程控制

- **具体分析**: 项目的能量主要花在确保 Agent 按正确步骤执行（8 条过程控制规则），但在"帮 Agent 理解什么是好结果"方面相对薄弱。缺少品质锚定（任务拆解的好坏标准）、评估维度（如何衡量拆解质量）、和迭代改进机制。

### 最高杠杆改进方向

1. **增加目标治理规则** — 补充品质锚定、评估维度、验收标准，让 Agent 理解"什么是好的任务拆解"
2. **增加迭代机制** — 任务执行后收集用户反馈，用于改进拆解策略

### 改进依赖关系

- 品质锚定和评估维度必须同步实施，因为没有品质锚定，评估维度无权重依据
- 迭代机制应在品质锚定+评估维度之后，因为需要评估结果作为迭代驱动力
- 触发条件量化可独立实施

## 发展方向

### 短期（1-2 周）

1. 量化触发条件 — 定义"复杂任务"的具体标准
2. 增加重试机制 — 子任务失败时自动重试（最多 3 次）
3. 增加验收标准 — 定义任务完成的验收条件

### 中期（1-2 月）

1. 增加品质锚定 — 定义"好的任务拆解"的标准
2. 增加评估维度 — 拆解粒度、依赖合理性、执行效率
3. 增加进度反馈 — 长时间执行时输出中间状态

### 长期（3-6 月）

1. 增加迭代机制 — 收集用户反馈，改进拆解策略
2. 增加学习能力 — 跨项目学习任务拆解模式
3. 增加组合能力 — 与其他 Skill 组合使用

## 用户接受策略

### 定位

- **目标用户**: 需要处理复杂任务的开发者
- **核心卖点**: 自动拆解任务 + 依赖管理 + 用户确认
- **一句话介绍**: "告诉我你要做什么，我帮你拆解成步骤，你确认后我逐步执行"

### 行动清单（你可以做的 5 件事）

1. **试用核心功能** — 给一个真实任务，看拆解结果是否合理
2. **测试依赖处理** — 给一个有依赖关系的任务，看执行顺序是否正确
3. **测试边界 case** — 给一个模糊任务，看 agent 如何处理
4. **测试错误处理** — 故意给一个会导致失败的任务，看错误提示是否清晰
5. **提供反馈** — 告诉 agent 哪些拆解不合理，帮助它改进
