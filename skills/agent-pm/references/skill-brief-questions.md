# Skill Brief Questions

> 新 skill 创建前的澄清问题库。进入模式 C 时读取，用来持续追问直到逻辑闭环。
>
> 使用规则：
> - 每轮最多问 3 个问题。
> - 优先问会改变 skill 设计方向的问题。
> - 不要机械问完整清单；只问当前 `SkillBrief` 的最高风险缺口。

---

## 1. 价值与用户

- 这个 skill 主要给谁用？是你自己、团队成员，还是某类外部用户？
- 它要解决的具体痛点是什么？现在不用 skill 时，你通常怎么解决？
- 这个任务是高频、复杂、易错，还是需要专业知识沉淀？
- 如果首版只解决一个场景，哪个场景最值得做？
- 用户用完后应该明显节省什么：时间、判断成本、查资料成本、格式错误、重复劳动？

闭环标准：能用一句话说清楚"为谁，在什么场景下，解决什么问题，产出什么结果"。

---

## 2. 触发条件

- 用户说什么话时应该触发这个 skill？
- 哪些相似请求不应该触发？
- 它是自动触发好，还是用户手动点名更安全？
- 如果请求只部分匹配，应该追问、拒绝，还是继续用通用能力处理？
- 它和已有 skill 是否有触发重叠？重叠时谁优先？

闭环标准：能写出清晰的 `description`，包含 USE FOR 和 DO NOT FOR。

---

## 3. 功能边界

- 这个 skill 必须做哪 3 件事？
- 哪些事看起来相关，但首版明确不做？
- 它负责"决策建议"、"生成文件"、"执行操作"，还是三者都有？
- 哪些操作必须先确认用户，不能自动执行？
- 哪些输入不完整时必须追问，不能靠猜？

闭环标准：有清楚的 must-have、non-goals、确认点和禁止自动执行项。

---

## 4. 输入与上下文

- 用户至少需要提供什么信息，skill 才能开始？
- 哪些信息可以从项目文件、历史上下文或 reference 中读取？
- 如果缺少关键输入，应该问哪几个问题？
- 是否需要读取现有代码、文档、网页、图片、表格或外部系统？
- 是否需要保存历史状态，避免下一轮从零开始？

闭环标准：能定义输入 schema 或最小信息集，并有缺失信息处理方式。

---

## 5. 工作流

- 从用户请求到最终输出，应该分几步？
- 哪些步骤必须按顺序执行？
- 哪些步骤可以跳过或按需执行？
- 每一步的产物是什么，下一步如何使用？
- 失败、信息不足、冲突、用户中断时怎么办？
- 是否需要限制循环次数、问题数量、重试次数或输出长度？

闭环标准：有主路径、分支、异常路径和停止条件。

---

## 6. 输出与交付

- 最终输出是建议、报告、代码、配置、文件，还是多种组合？
- 输出要给人看，还是要给程序继续处理？
- 是否需要固定模板、字段、JSON/YAML/Markdown 格式？
- 什么信息不能出现在输出里？
- 是否需要保存到文件？保存前是否要确认？

闭环标准：输出格式、字段、质量标准和保存策略明确。

---

## 7. 资源与工具

- 这个 skill 只靠指令就够，还是需要 references、scripts、assets？
- 是否有稳定模板、清单、示例或领域知识应该放进 reference？
- 是否有容易出错的重复操作应该做成 script？
- 是否需要调用 MCP、浏览器、GitHub、文件系统或其他工具？
- 工具失败时有没有 fallback？

闭环标准：知道首版目录结构和每个资源存在的理由。

---

## 8. 验收与测试

- 用什么样的真实请求可以验证首版 skill 可用？
- 好输出和坏输出分别长什么样？
- 哪些错误一出现就说明 skill 设计失败？
- 是否需要 golden examples 或 eval cases？
- 首版完成后，用户如何判断"够用了"？

闭环标准：至少有 2 个真实测试请求、明确通过标准和失败标准。

---

## 9. 收束问题

当信息已经接近闭环时，优先问这些问题：

- 如果只能保留一个核心能力，这个 skill 最应该保留什么？
- 哪个边界最容易被模型误判？
- 哪个环节最不能靠模型自由发挥？
- 哪个输出最能让用户立刻感受到价值？
- 首版最小可用版本应该砍掉什么？

---

## 10. 评估与迭代

> 来源：Harness Engineering + Loop Engineering。核心问题：怎么判断 Agent 做得好不好？做不好时怎么改进？

- 你希望怎么判断 Agent 的产出是"好的"？只是功能对（pass/fail），还是品质也要达标（评分）？
- 如果 Agent 第一次做得不好，流程中有没有让它看到评估结果并改进的环节？
- 改进循环最多跑几轮？什么时候该接受当前结果不再迭代？
- 执行者和评估者需要信息隔离吗？执行者能看到评测标准吗？评估者能看到实现思路吗？
- Agent 在执行过程中能"看到"运行结果吗（截图、测试输出、DOM 快照）？

闭环标准：有评估方案（怎么判好）、迭代循环（做不好怎么改）、退出条件（什么时候停）和信息隔离策略（如果适用）。
